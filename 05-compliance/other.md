# Other frameworks to check

- **eIDAS as amended by Regulation (EU) 2024/1183:** EUDI Wallet relying party registration for each tenant using wallet verification (O-08). Signature level choice for contracts (O-18).
- **PSD2 (Directive (EU) 2015/2366):** execution mode must keep the platform outside payment services. The tenant's own bank executes (I-16).
- **NIS2:** check whether the SaaS falls in scope as a cloud computing service given size thresholds (O-07).
- **Grant agreements:** if platform build costs are charged to SuperSAFE or another action, check access rights of other beneficiaries to results (O-03).

## Funding of the build (O-03)

The platform build is self-funded by CrabNebula Ltd. Keep build costs in separate cost records, so the platform is never reported as a result of SuperSAFE or another action. If CrabNebula later charges SaaS use to an action it participates in, check that action's grant agreement rules on internally invoiced services before invoicing.

## Operating entity (O-07)

CrabNebula Ltd operates the SaaS and is the contracting party towards tenants. NIS2 scope for the SaaS depends on CrabNebula's size against the medium-sized enterprise thresholds and on the Maltese transposition. Re-check scope at each annual accounts closing.

Where CrabNebula also runs a programme as tenant operator, as for SuperSAFE, it is controller for that tenant's data. No processor agreement exists for that tenant, but the same cell isolation and break-glass rules apply (SoD-08, TH-18).
